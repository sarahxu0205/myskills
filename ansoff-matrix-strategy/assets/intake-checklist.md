# 信息收集清单

## 一、信息分级

| 档位 | 判定标准 | 首轮动作 |
|---|---|---|
| L1 | 三要素（卖什么 / 卖给谁 / 卡在哪）缺任一 | 快速决策卡 + 最多 3 个追问 + "继续"选项 |
| L2 | 三要素齐，但"规模信号 / 量化目标 / 时间窗 / 硬约束"缺任一 | **只追问 ≤3 个关键问题，不输出方案**；回答或"继续"后出标准方案 |
| L3 | 三要素齐 + 规模/营收 + 量化目标 + 时间窗 + 至少 1 项硬约束 | 直接出标准方案；明确要求时出深度方案，不追问 |

**规模信号**：营收、付费用户数、月活、安装量、粉丝数、员工数、门店数，任一项即可；不要求必须是营收。

**判定顺序**：三要素 → 规模信号 → 量化目标 → 时间窗 → 硬约束，按顺序判，不跳步。

**判定示例**：
- AI 写作助手、自媒体客群、月活 2000、付费转化 2%、想提高收入 → L2，首轮追问，不直接出方案。
- 火锅店、夏天没人来 → L1（客群不清），快速决策卡 + 追问。
- SaaS、50 人、年营收 800 万、月流失 15%、目标 12 个月降到 9%、研发预算 50 万 → L3，直接出方案。

## 二、信息项优先级

> "重要"只影响分析精度，不触发追问；L2 的缺失项在追问一轮后按假设处理，L3 缺失项不存在（四项必须齐全）。

| 信息项 | 必要性 | 缺失时的影响 |
|---|---|---|
| 行业与基本业务 | 必填 | 无法定位行业先验 |
| 核心产品/服务 | 必填 | 无法判断象限归属 |
| 目标客群 | 必填 | 无法区分现有市场与新市场 |
| 核心痛点/增长问题 | 必填 | 无法确定分析目标 |
| 规模（营收/付费用户/月活/员工/门店，任一项） | 重要 | 无法判断资源约束，按档假设 |
| 增长目标与时间窗 | 重要 | 无法测算增长缺口，按档假设 |
| 淡旺季情况 | 重要（季节性行业） | 无法叠加淡旺季专项 |
| 主要渠道与区域 | 可选 | 市场开发分析偏粗 |
| 主要竞争对手 | 可选 | 竞争强度评分依赖假设 |
| 预算与团队约束 | 可选 | 资源匹配度评分偏乐观 |

## 三、追问话术（仅 L1 / L2 使用；L3 禁止追问）

优先问"能改变结论"的信息，按以下顺序取前 3 个：

1. **规模/营收**："目前大概什么体量？营收、付费用户数、月活，任一项即可。"
2. **量化目标**："希望多久内、把哪个指标做到什么水平？比如收入、付费转化或客户数。"
3. **时间窗**："这个目标是 3 个月、6 个月还是 12 个月？"
4. **硬约束**："预算、人手或现金流上有什么硬限制？"
5. **客群结构**："收入主要来自哪类客户？大概占比如何？"
6. **淡季成因**（季节性业务）："淡季是客人不来，还是来了接不住？"

**追问规则**
- 仅 L1、L2 使用；L3 跳过本节，禁止追问。
- 每档只追问一轮，最多 3 问；问完即停，不连续追问。
- 每个问题后说明"不回答也可以，回复'继续'我会按假设出方案"。
- 用户拒绝补充或只说"继续"时，不再询问，直接输出对应方案。

## 四、默认假设表（信息缺失时使用）

| 缺失信息 | 默认假设 | 标注方式 |
|---|---|---|
| 规模 | 单店/小微团队（年营收 100-1000 万） | "按小微体量假设（待验证）" |
| 增长目标 | 年增 20-30% | "按年增 25% 测算（待验证）" |
| 客群 | 以本地 C 端为主 | "假设 C 端为主（待验证）" |
| 渠道 | 线下为主、线上为辅 | "假设线下为主（待验证）" |
| 竞争强度 | 中等（有 2-3 家强势对手） | "竞争强度按中等估计（待验证）" |
| 淡旺季 | 无明显季节性 | "假设季节波动不显著（待验证）" |

**要求**：所有假设必须集中写入报告的"假设与数据来源"栏，并给出验证方式，不得当作事实使用。
