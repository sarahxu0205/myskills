# HIT方法论详解

> **定位**：本文只回答「为什么成立」「怎么做得更好」「失败长什么样」。
> 流程顺序与硬性约束以 `SKILL.md` 为准；评分口径以 `references/evaluation-criteria.md` 为准。本文不重复定义任何规则。

## 术语表

| 术语 | 定义 | 常见误用 |
|---|---|---|
| 领域 | 被借用的外部系统：可以是学科、行业、组织形态或自然现象 | "我们的竞品"——那是同域对照，不是对比领域 |
| 机制 | 领域内部让某事稳定发生的因果结构：谁在什么条件下做了什么，从而产生什么 | "游戏化"——这是标签，不是机制 |
| 特性 | 领域表面可观察到的功能、形态或风格 | "有积分商城"——形式，不可迁移 |
| 约束 | 目标问题里不可回避的限制，能判定"能不能 / 多久 / 谁批准" | "要做得更好"——不是约束 |
| 效果 | 机制在约束下产生的可观察结果 | "体验更好"——不可观察 |
| 维度桶 | 领域的粗分类，用来保证跨域多样性 | 按"行业"分类——容易落回相邻行业 |
| 机制句 | 唯一可迁移的产出单位：`【领域】通过【机制】，在【约束】下产生【效果】` | "参考一下 ICU"——没有机制，无法迁移 |

## 一、HIT 的认知基础与边界

### 1.1 四条原理

1. **类比思维**：类比是人类产生新想法的核心认知机制。
2. **远距离联想**：创造力来自看似无关概念之间的连接。
3. **特性转移**：把一个领域被现实检验过的结构搬到另一个领域。
4. **组合创新**：两条机制叠加，产生单条机制不具备的新结构。

### 1.2 为什么有效

- **强制跳出默认框架**：跨域对比不允许沿用目标行业的现成答案。
- **降低创新门槛**：不从零发明，而是借用已被验证的因果结构。
- **提高结构差异度**：HIT 追求的不是"点子更多"，而是"结构不同"。
- **可重复**：把依赖灵感的环节拆成可检查的步骤。

### 1.3 与其他创新方法的边界

| 方法 | 核心机制 | 适用场景 | 与 HIT 的差异 |
|---|---|---|---|
| 头脑风暴 | 自由发散 | 需要大量创意 | HIT 的结构化更强，联想有因果链 |
| SCAMPER | 检查表式改造 | 改进现有产品 | HIT 更适合突破性创新 |
| 设计思维 | 用户中心 | 解决用户问题 | HIT 补充跨领域灵感，不替代用户研究 |
| TRIZ | 技术矛盾解决 | 技术问题 | HIT 不限于技术，也不要求矛盾可参数化 |
| 六顶思考帽 | 多角度思考 | 团队讨论 | HIT 提供具体的迁移单位（机制） |
| 竞品分析 | 同域对照 | 找差异化卖点 | 竞品分析保证不落后，HIT 才有机会不相似 |

### 1.4 一句话边界

HIT 负责"想出没人做过的新方案"，不负责市场验证、时机判断与执行落地。不适用清单见 `SKILL.md`「适用 / 不适用」。

## 二、机制：从现象到机制句

### 2.1 形式、特性、机制

| 层级 | 例子（以 ICU 交班为例） | 能否迁移 |
|---|---|---|
| 形式 | 白板、交班表格、签字笔 | 不能，换场景就成了道具 |
| 特性 | 每班交接一次、双人核对 | 只能部分，容易僵化 |
| 机制 | 责任在交接点显式转移，未确认即升级 | 能，可跨场景复用 |

判断问句：**把专有名词、设备名、岗位名全部删掉后，这句话还成立吗？** 成立才是机制。

### 2.2 剥离三步

1. **删形态**：去掉界面、设备、岗位名称与行业术语。
   例："护士站白板交班" → "交班"。
2. **找结构**：只问三件事——谁负责？什么条件下触发？失败时由谁接手？
   例："交班" → "上一责任人把未完成项交给下一责任人，接收方确认，未确认则升级"。
3. **压成句**：按固定格式写。
   例："ICU 通过「口头交班 + 双方签字确认」，在信息需要跨班次转移的约束下，让责任不留空档。"

### 2.3 五种失败写法与改写

| 失败类型 | 典型写法 | 问题 | 改写 |
|---|---|---|---|
| 功能名 | "用药提醒" | 这是产品功能，不是机制 | "在固定时点触发一次必须被回应的确认" |
| 界面 | "做一个大屏看板" | 形态不可迁移 | "把隐性状态变成公共可见状态" |
| 口号 | "以人为本" | 无法执行 | "把决策权交给离现场最近的人" |
| 过抽象 | "借鉴生态系统的协同" | 没有因果结构 | "个体失效时由邻居按阈值补位" |
| 因果缺失 | "用排队论优化" | 只给了工具名 | "用等待时间上限反向限制到达速率" |

### 2.4 机制提取的五个观察面

| 观察面 | 追问 | 常见可迁移机制 |
|---|---|---|
| 约束 | 这个领域最缺什么？它怎么在缺的条件下运转？ | 资源替代、降级运行、分级响应 |
| 角色与责任 | 谁对结果负责？责任怎么转移？ | 交接确认、双签、责任上收 |
| 信息流 | 什么信息在什么时候被谁看到？ | 状态外显、异常上报、盲区暴露 |
| 激励与结算 | 谁为什么付钱？按什么计量？ | 按效果结算、互惠交换、抽成 |
| 异常处理 | 出错时怎么兜底、升级、回滚？ | 熔断、隔离、升级、回滚 |

选哪个面由用户决定（引导话术见 `references/ideation-prompts.md`），但不论选哪个面，最终都必须压成机制句。

## 三、找"远"领域

### 3.1 四条选择原则

- **跨域性**：与目标明显不同。
- **启发性**：有值得借的结构，而不只是"听起来高级"。
- **多样性**：3-5 个领域来自不同桶。
- **可迁移性**：存在能说清的底层逻辑，而不是靠感觉联想。

距离判定（3 问）见 `SKILL.md` 闸门 4，此处不重复。

### 3.2 六桶种子领域库

用法：先选桶，再抽 1-2 个；**不要按"和目标像不像"挑**，那会直接落回相邻行业。

**自然仿生**

1. 菌根网络（资源在个体间定向输送，互惠交换）
2. 蜂群选址（多候选点用阈值投票收敛）
3. 免疫系统（记忆细胞 + 快速二次响应）
4. 森林冠层空隙（局部干扰制造多样性）
5. 珊瑚共生（宿主与共生体分工）
6. 动物冬眠（周期性降载，度过资源枯竭）
7. 火生态（定期小火烧掉积累的可燃物）
8. 蚁群路径（信息素正反馈 + 挥发遗忘）
9. 种子休眠（延迟启动，等待触发条件）
10. 细胞凋亡（主动淘汰异常单元）

**社会系统**

1. 城市消防分区（隔离带 + 定期演练）
2. 陪审团（随机抽样 + 强制共识）
3. 战地分诊（按可救性排序，而非先来后到）
4. 开源社区维护者制度（提交权分级）
5. 行会学徒制（师徒绑定 + 出师考核）
6. 城市排水系统（按重现期设计，而非按最大值）
7. 信用合作社（成员共同担保）
8. 邮政普遍服务义务（亏损线路也必须覆盖）
9. 社区调解（熟人压力替代诉讼）
10. 应急物资轮换（先进先出 + 有效期）

**体验服务**

1. 日间手术中心（准入评估 + 标准路径 + 异常升级）
2. 米其林后厨（分工站位 + 出餐节拍）
3. 酒店管家（单一联系人 + 需求预判）
4. 航空值机（超售与候补的排队规则）
5. 急诊分诊（严重度优先）
6. 主题公园快速通行（时间预约替代排队）
7. 蒙台梭利教室（混龄 + 自主选择）
8. 殡葬服务（用仪式节点管理悲伤节奏）
9. 体育联赛升降级（末位淘汰）
10. 剧场中场休息（把长流程切段）

**技术工程**

1. 微电网黑启动（孤岛自治 + 恢复并网）
2. 数据库预写日志（先写日志再改数据）
3. 电路断路器（故障隔离 + 半开试探）
4. 分布式共识（多数派确认）
5. 灰度发布（小流量验证 + 可回滚）
6. 集装箱标准化（接口统一，内部自由）
7. 旁站监理（关键工序第三方在场）
8. 飞机冗余系统（多套独立系统 + 交叉检查）
9. 铁路信号闭塞（区间占用互斥）
10. 版本控制（每次变更可回溯）

**艺术人文**

1. 交响乐排练（分声部到合奏的收敛）
2. 电影分镜（先低成本粗剪，再精修）
3. 侦探小说的线索投放（用信息差制造张力）
4. 书法临帖（先临后创）
5. 戏剧的幕与场（用结构切分时间）
6. 爵士乐的即兴框架（约定和弦内自由）
7. 博物馆策展动线（用叙事顺序控制注意力）
8. 诗歌格律（约束反而催生表达）
9. 雕塑的减法（去掉多余而非添加）
10. 建筑的空间序列（用过渡空间改变预期）

**商业运营**

1. 特许经营（SOP + 督导 + 分成）
2. 保险精算（用大数分摊个体风险）
3. 供应商管理库存（供应商管库存）
4. 二手交易担保（第三方托管，验货后放款）
5. 仓储会员店选品（少 SKU + 大包装）
6. 拍卖机制（英式 / 荷兰式决定价格发现方式）
7. 寄售（卖出后才结算）
8. 便利店加盟订货指导（总部给建议，店主决定）
9. 团购成团阈值（不到人数不成交）
10. 订阅制报刊（定期投递 + 漏投补发）

### 3.3 采样规则

- 3 个桶起，5 个封顶。
- 同桶最多 2 个，且不能同族（蜂群与蚁群算同族，只取一个）。
- 至少 1 个"非商业、非互联网"领域。
- 用户自带领域时，先做距离判定，再决定是否补充。

### 3.4 距离自检

每个领域后面写一句：`来自【桶】；与目标共享的词是【X】；如果不跨域，会错过【Y】`。
写不出 Y，说明这个领域只是"看起来相关"，换掉。

## 四、联想的四条路径与组合扫描

### 4.1 四条路径

| 路径 | 做法 | 例子 |
|---|---|---|
| 特性映射 | 结构对结构，一一对应 | ICU 交班确认 → 每日用药确认单 |
| 跨界组合 | A 机制 + B 机制 | 分诊排序 + 订阅投递 → 按风险排随访优先级 |
| 场景迁移 | 同一机制换场景 | 消防演练 → 用药流程的无预警抽检 |
| 原理借鉴 | 只取因果，不取形式 | 火生态"定期小火烧掉积累风险" → 定期清理积压投诉 |

### 4.2 组合扫描（先求量，再收敛）

1. 把各领域的机制拆成清单（3 个领域 × 1-2 条 ≈ 5-8 条）。
2. 机制两两组合，逐对追问"叠加后能解决目标问题的哪个约束"，先写满 8-12 条，不评判。
3. 按 `SKILL.md` 闸门 1/2/3 过滤，收敛到 3-5 个方案。

示例：`责任交接` × `按效果结算` → 服务方只有在"交接被确认"后才计费，未确认不计费且自动升级。

组合扫描的价值：单条机制通常只是"参考"，两条叠加才容易出现没人做过的新结构。

## 五、机制的有效期与稀缺性

### 5.1 三层价值

| 层级 | 价值来源 | 耐久度 |
|---|---|---|
| 结构价值 | 改变责任、信息或激励的结构 | 高，较难被抄走 |
| 信息价值 | 让原本不可见的状态可见 | 中，容易被跟风 |
| 激励价值 | 积分、等级、奖励 | 低，很快饱和 |

### 5.2 稀缺性检验三步

1. **搜**：目标领域关键词 + 机制关键词组合搜索，看是否已有产品在用。
2. **对**：列 3 个最接近的竞品，逐个看是否已具备该机制；有就是饱和。
3. **问**：找 3-5 个目标用户问"你现在怎么做的"；如果对方回答"我们一直这么干"，机制已被脱敏。

### 5.3 时间衰减

同一个机制在不同时间点稀缺性不同。积分、等级、排行榜在教育产品里曾经是创新，今天已是标配（见 9.3）。判断标准不是"机制好不好"，而是"目标用户是否已被它饱和覆盖"。

### 5.4 组合提高稀缺度

优先级：冷门机制 > 机制组合 > 单条常见机制。两条常见机制组合出的新结构，往往还没人做过。

## 六、约束建模

### 6.1 五类约束

| 类型 | 追问 | 例子 |
|---|---|---|
| 资源 | 预算、人力、时间的上限？ | 只能 2 人做 3 个月 |
| 合规 | 哪些事不能做？谁审批？ | 医疗数据不能出院内 |
| 组织 | 谁必须配合？跨部门吗？ | 需要社区医生排班参与 |
| 用户习惯 | 用户现在怎么做？愿意改吗？ | 老人不用智能机 |
| 技术底座 | 现有系统能接吗？ | 老系统没有 API |

### 6.2 可判定写法

约束必须能回答"能不能 / 多久 / 谁批准"。

- ❌ "预算有限"——无法判定方案是否越界。
- ✅ "首版 ≤ 5 万，且不能新增编制"——可以直接筛掉方案。

### 6.3 反向用法

`约束 → 需要的机制 → 反选领域`。

例：约束是"没有 IT 维护能力" → 需要"降级运行 + 远程接管" → 微电网黑启动、飞机冗余系统、动物冬眠。

## 七、从方案到最小验证实验

### 7.1 四要素

| 要素 | 写法 | 例子 |
|---|---|---|
| 假设 | 如果【机制】成立，那么【行为】会变化 | 如果交接确认可见，未确认率会下降 |
| 动作 | 一周内能做完的最小动作 | 纸质交接单跑 7 天 |
| 指标 | 1 个主指标 + 1 个护栏指标 | 主：未确认次数；护栏：额外耗时 |
| 阈值 | 达到多少算通过 | 未确认率下降 50%，且额外耗时 < 2 分钟/次 |

### 7.2 四种一周内可做的形态

- **纸质流程**：不上系统，先用纸跑通。
- **人工扮演**：人装作系统，验证流程是否成立。
- **单点灰度**：只在一个班组、一个门店试。
- **对照组**：试的与不试的，比同一指标。

### 7.3 两个反例

- ❌ "做个 App 上线看看"：周期长、变量多，失败后不知道败在哪。
- ❌ "发问卷问用户喜不喜欢"：态度指标，不能替代行为。

### 7.4 指标优先级

行为 > 留存 / 复购 > 态度。能用行为指标就不用满意度。

## 八、失败模式与降级路径

### 8.1 六个陷阱

| 陷阱 | 表现 | 处理 |
|---|---|---|
| 领域太近 | 术语重合、同价值链、用户重叠 | 按闸门 4 判近，换领域 |
| 表面模仿 | 抄了形式，没抄机制 | 机制句写不出就丢弃 |
| 忽视可行性 | 技术或资源不成立 | 用第六节的约束建模反查 |
| 联想牵强 | 因果链断裂 | 写不出"因为…所以…"就丢弃 |
| 信息不全就生成 | 痛点靠猜 | 标注"推断"，给用户补充机会 |
| 把标配当创新 | 迁移了已饱和机制 | 走 5.2 三步检验 |

更细的规则解释见 `SKILL.md` 质量闸门，此处不重复。

### 8.2 跑完仍无合格方案：四级降级

1. **换桶**：当前领域集中在 1-2 个桶，补 2 个远桶。
2. **换层**：产品层 → 流程层 → 商业模式层 → 组织层，同一机制换层迁移。
3. **反向 HIT**：从机制出发问"它还能解决谁的问题"，再回到目标问题。
4. **缩小目标**：把"创新一个平台"缩成"创新一个环节"；目标越小，机制越容易落地。

四级都不行，说明目标本身可能不适合 HIT（例如只是要优化现有功能）。停用条件见 `SKILL.md`「适用 / 不适用」。

## 九、案例复盘

### 9.1 Velcro（历史案例）

- **机制**：钩状结构通过密集微小接触点，在反复开合的场景下提供可拆卸固定。
- **迁移与时效**：从牛蒡种子到织物扣件；钩环机制今天已不稀缺，新的机会在约束（无胶、可降解、静音）。

### 9.2 快递柜（历史案例）

- **机制**：模块化存储 + 自助取件 + 身份验证，把"人对人交付"改成"人对柜交付"。
- **迁移与时效**：蜂巢、酒店前台、自动售货机三条机制叠加；这三点已是城市基础设施，单靠它们不再构成差异化。

### 9.3 游戏化学习（反例）

早期把积分、等级、排行榜、成就搬到学习产品上确实有效，但那是因为当时没人这么做。今天这套机制在教育产品里已经饱和，再拿它当核心创新点就是套路。

**结论**：同一个机制在不同时间点的稀缺性会变。判断标准不是"这个机制好不好"，而是"现在的用户是否已经被它饱和覆盖"。

### 9.4 用药交接单：推导复盘

只复盘推导过程，完整方案见 `SKILL.md`「黄金示例」。

1. 目标解构后发现，真正的痛点是"提醒了但没人确认"，不是"忘记提醒"。
2. 因此要找的机制是**责任转移**，不是**通知**。
3. ICU 交班提供的正是"确认 + 未确认即升级"，而不是又一次提醒。
4. 迁移时丢掉 App、丢掉打卡、丢掉积分，只留交接单与升级链。
5. 过闸门 1：最接近的是分药盒 + 提醒 App，差异是"提醒是否发出"变成"责任是否交接"。
6. 过闸门 3：因为交班确认能解决"没人对结果负责"，所以用药流程可以改成按天交接。

**可复用的判断**：当一个方案只能回答"我们也能提醒"，说明机制选错了；能回答"我们让责任无法落空"，才是换掉了范式。
