# SCAMPER 引导话术库

本文件只放话术。规则、闸门、评分口径以 `SKILL.md` 为准，不在本文件重复。

## 一、首次响应（基础级：缺对象或缺痛点）

```
可以，我用 SCAMPER 七维法帮你做系统性创新分析。为了避免基于猜测出方案，先确认三件事：

1. 现在最头疼的问题是什么？（成本高 / 效率低 / 体验差 / 同质化 / 增长停滞 / 质量不稳 / 收入单一）
2. 现在的做法是什么？它为什么不够好？（至少两条）
3. 有哪些硬约束？（预算、时间、技术、法规、不能动的东西）

回答后我会给出：七维改进创意 + Top3 优先级 + 验证方式。
不方便逐条回答的话，回复"你看着办"，我会按推断输出并标注。
```

用户只给出对象、没有痛点时，用这段话追问，不要先出分析；用户已给出对象 + 痛点时，直接进入分析，并在结论后输出关键假设。

## 二、信息补全（缺口提问，≤3 问）

```
为了把 Top3 排得更准，还需要确认：

1. 现有做法是什么？它为什么不够好？
2. 约束条件：预算、时间、技术或法规上有哪些限制？
3. 你希望达到什么可衡量的结果？

这些会直接影响评分与排序。不方便逐条回答的话，回复"你看着办"，我会按推断输出，并把推断项放进关键假设。
```

第二轮只问仍然缺的项，最多 2 问。之后不再追问。

## 三、七维引导（一句话版）

需要逐维展开时使用，每次只问一个维度，不要一次抛七个问题。

| 维度 | 引导话术 | 禁忌问法 |
|---|---|---|
| 替代 S | 现在的哪个部件、角色、材料或技术，换成别的也能完成任务？ | "有什么可以替代的？"（太宽） |
| 结合 C | 它能不能和用户已有的另一个动作/工具并用，省掉一次切换？ | "可以和什么结合？"（容易凑功能） |
| 适应 A | 哪类用户、哪个时段、哪种场景现在被放弃了？改动哪里能接住他们？ | "如何适应更多用户？"（空） |
| 修改 M | 哪个规格最影响体验：时长、粒度、强度、距离、频率？放大或缩小会怎样？ | "如何优化体验？"（空） |
| 他用 P | 这套能力还能卖给谁、用在什么别的任务上？ | "还能用在哪些场景？"（易泛泛） |
| 删除 E | 哪一步、哪个字段、哪个环节删掉后，用户反而更愿意用？ | "如何简化流程？"（空） |
| 重排 R | 哪个顺序倒过来做、哪个环节前置会更快？ | "如何优化流程？"（空） |

## 四、重生成话术（用户说"太普通 / 不够新"时）

每轮只开一种手法，开场先说明换了什么：

**手法 1 · 抬高一层**

```
这一轮我把视角从功能层抬到商业模式层重扫：不改界面，只改"谁付费、谁交付、谁受益"。
```

**手法 2 · 反向 SCAMPER**

```
这一轮反过来：把行业里最主流的做法当作要被删除或逆向的对象，问"完全不这么做会怎样"。
```

**手法 3 · 极端约束**

```
这一轮加极端约束：假设预算为 0、用户只给你 30 秒、或者必须删掉一个核心功能，还剩什么做法？
```

**手法 4 · 换对象类型重扫**

```
这一轮把对象换个类型重看：把它当服务（或当流程）重新跑一遍七维，原来的盲区会露出来。
```

**手法 5 · 跨域机制迁移**

```
这一轮从三个远处借机制：医院交班、航空值机、便利店补货，各取 1 条机制迁移到你的对象上。
```

收尾统一说明：`本轮淘汰了 X 条（理由），新增 Y 条，编号续编不重排。`

## 五、深化话术（用户选定某条方案后）

```
方案【编号】可以往五个方向深化，选一个：

1. 机制：这条创意为什么有效，依赖哪个用户假设
2. 用户：具体服务谁，他们在什么场景下会用它
3. 边界：什么情况下这条方案会失效
4. MVP：两周内能验证的最小版本
5. 商业：谁付费、成本结构怎么变
```

## 六、关键假设声明

进阶级及以上、且存在影响排序的推断时，在结论后加一段：

```
## 关键假设（待确认）

1. 【推断】<假设> → 影响 <哪一维评分 / 哪个方案>
2. 【推断】<假设> → 影响 <...>

修正任意一条后，我会重算评分并重排 Top3。
```

无关键推断时写：`关键假设：无（关键信息已齐全）。`

## 七、特殊处理

### 用户拒绝补充信息

```
明白，我按现有信息做，推断的部分会标【推断】，你看到不对的地方直接指出，我再校正。
```

### 用户只要文字

```
好，这次不生成报告文件，只给文字版；需要可视化时随时说。
```

### 用户要跳过某维度

```
可以跳过。我会保留一行说明"该维度本次未展开"，其余维度不受影响。
```

### 用户输入过于宽泛

```
"创新"这个范围有点大，建议先锁定一个具体对象，例如一个产品功能、一项服务流程、一个用户场景。
你现在最想改的是哪一个？
```

### 用户要求违规方案

```
这个方向涉及诱导或欺骗用户，我不做。可以换一个不依赖操纵手段的做法：把同样的目标（提升转化/复购）用"降低决策成本"来实现，需要我给两条吗？
```
