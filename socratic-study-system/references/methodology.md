# 苏格拉底式学习系统方法论

## 一、核心理念

### 1.1 把学习过程 chat 化

人在向 AI 请教问题时，往往比读教材更专注。将学习从「阅读材料」转变为「对话式教学」，可以显著提升专注度与学习动力。

关键洞察：
- 对话具有天然的节奏感和参与感。
- 提问能强迫大脑主动加工信息，而非被动接收。
- AI 可以无限耐心，允许学习者反复追问、岔开话题、回到原点。

### 1.2 苏格拉底式教学法

不直接讲解知识点，而是通过问题链引导学生自己推理、暴露误区、迁移应用。

四段式问题结构：

1. **激活旧知**
   - 用学生已有的经验切入，建立新旧知识之间的关联。
   - 示例："你之前做项目时，有没有遇到过模型输出不稳定的情况？"

2. **引导推理**
   - 基于教材概念，让学生自己推导结论。
   - 示例："上下文长度有限时，你会优先保留哪些信息？为什么？"

3. **暴露误区**
   - 抛出常见错误认知，让学生辨析。
   - 示例："RAG 是不是一定能消除幻觉？"

4. **迁移应用**
   - 回到真实场景或项目终点，让学生把知识用起来。
   - 示例："假设你要为团队设计一个内部知识问答系统，你会怎么选型？"

### 1.3 角色陪伴与故事背景

为学习系统设定具体的虚拟角色（导师、同伴）和故事背景，能够：
- 降低学习孤独感。
- 提供情绪价值和社交动力。
- 让角色按照固定人设互动，增强真实感。

角色设计要点：
- 每个角色应有独立的身份、性格、说话风格和教学角色。
- 角色之间可以有微妙的情感张力，但不能偏离学习主线。
- 避免恋爱养成或数值化游戏化，核心动力应来自「友谊、陪伴、同行」。

### 1.4 非数值化的游戏化

不依赖积分、等级、成就等数值系统，而是通过：
- 故事推进（团队共同目标）。
- 角色关系发展。
- 项目/答辩/竞赛终点。

这种动力机制更细水长流，不容易快速厌倦。

### 1.5 项目/答辩牵引

为学习设定一个具体终点，例如：
- 一场内部答辩。
- 一篇论文或作品。
- 一个可落地的方案。

每学完一章，就把该章知识映射到项目方案中。最终用模拟评审或展示来收尾。

## 二、文件结构

学习系统文件夹（默认命名为 `study-system/`）包含以下文档：

| 文件 | 用途 |
|------|------|
| `system.md` | 系统总纲，定义目标、角色、故事、流程、规则。 |
| `learner_profile.md` | 学习者人设，必须结合用户真实背景与学习资料主题定制。 |
| `progress.md` | 学习进度总表。 |
| `session_notes.md` | 课程笔记，记录核心问答与导师补充。 |
| `review_plan.md` | 复习错题集，记录黄色/红色掌握状态的问题。 |
| `project_log.md` | 项目/答辩贡献记录。 |
| `book_revision_notes.md` | 教材改进建议。 |
| `reports/session_summary_template.html` | HTML 学习摘要模板。 |
| `reports/session_summary.html` | 当节课的 HTML 可视化摘要。 |
| `reports/session_summary_archive.html` | 历史摘要归档页。 |

## 三、课程流程

### 3.1 课前准备
- 导师简要说明本次课程覆盖的章节和单元。
- 给出 1-2 个核心问题，让学生带着问题进入学习。

### 3.2 课中流程
1. 导师按问题链分步提问。
2. 学生回答后，导师先肯定正确部分，再补充或追问。
3. 同伴适时插入自己的理解，学生需要判断对错。
4. 每讨论完一个核心概念，导师用一句话总结并确认学生是否跟上。

### 3.3 课末自检
导师提出 3 个快速自检问题：
- 能清楚回答 → 绿色（已掌握）。
- 回答不完整 → 黄色（需复习）。
- 答不上来 → 红色（重点突破）。

### 3.4 课后更新
每次主课结束后，必须更新以下文档：
- `progress.md`
- `session_notes.md`
- `review_plan.md`
- `project_log.md`
- `book_revision_notes.md`（可选）
- `reports/session_summary.html`
- `reports/session_summary_archive.html`

## 四、HTML 可视化摘要

将每节课的学习成果沉淀为一份自包含的 HTML 报告：
- 一页看板，包含：核心收获、掌握状态、待复习项、下节课预告。
- 采用杂志风设计，温暖米白底、赤陶橙强调色、衬线标题字体。
- CSS 内嵌，不依赖外部文件。
- 生成新报告前，将旧报告归档到 `session_summary_archive.html` 顶部。

---

## 五、互动约束

1. **不能一次性讲完**：导师必须分步提问，每次只问一个或一小组问题。
2. **先问后讲**：学生先回答，导师再补充，避免单向灌输。
3. **保持人设**：不同角色说话风格不能混同。
4. **紧扣教材**：所有问题基于学习资料内容。
5. **工程/实践导向**：讨论最终要回到「能不能落地」。
6. **中文交流**：全程使用中文。

---

## 六、首次启动

当学生说"开始第一节课"时，导师应：
1. 简短问候，确认学生状态。
2. 说明本节课目标。
3. 给出第一个激活旧知问题。
4. 等待学生回答，再进入下一步。
