# HTML 可视化报告生成规范

## 一、何时生成（默认）

HTML 报告默认随分析一起生成，不再等待用户要求。

| 场景 | 是否生成 | 版本 |
|---|---|---|
| 快速版 | 是 | 简版 |
| 标准报告 | 是 | 完整版 |
| 深度方案 | 是 | 完整版 + 情景与 12 个月路线图 |
| 二次聚焦分析 | 是 | 聚焦版 |
| 信息补全请求 | 否 | — |
| 假设版 | 否（用户明确要求时才生成） | 假设简版 |
| 用户明确说"只要文字/不用报告" | 否 | — |

本规范适用于软件产品、实体服务、课程、社群等任何有明确用户与价值的产品形态。

---

## 二、版本与模块

| 模块 | 快速版 | 标准/深度 | 聚焦版 | 假设版 | HTML 区块 |
|---|---|---|---|---|---|
| 分析边界与假设 | 是 | 是 | 是 | 是（标注缺失项） | 头部元信息 + 边界条 |
| 产品/服务概况 | 简要 | 是 | 简要 | 简要 | 头部信息区 |
| 九窗矩阵 | 是（每窗 1 条） | 是（每窗 2-3 条） | 是（每窗 1-2 条） | 是（全部标假设） | 3×3 矩阵网格 |
| 逐窗分析 | 矩阵格内 | 独立章节 | 矩阵格内 | 矩阵格内 | 矩阵 / 正文 |
| 跨窗洞察与矛盾 | 1 条关键矛盾 | 3-5 条，含矛盾/时间链/层级链 | 1 条关键矛盾 | 1 条假设矛盾 | 洞察卡片 |
| 机会清单 | 3 个简卡 | 全部机会卡（含推导链/评分/置信度） | 不展开 | 不展开 | 机会卡 |
| 优先级评估 | 否 | 是 | 否 | 否 | 评分表 + 分数条 |
| TOP3 方案 | 否 | 是 | 否 | 否 | 三张详情卡 |
| 90 天计划 | 是（仅第一步） | 是 | 是（验证计划） | 否 | 三阶段路线图 |
| 假设与信息缺口 | 简要 | 是 | 是 | 是 | 底部信息区 |
| 页脚 | 是 | 是 | 是 | 是 | 页脚 |

**简版**必须保留：头部、边界、九窗矩阵、关键矛盾、3 个机会、先做一件事（复用路线图第一阶段）。不得删到只剩 3 段摘要。

**完整版**必须保留：评分表、TOP3、90 天计划；深度版再追加情景分析和 12 个月路线图。

**聚焦版**必须保留：新系统边界、聚焦九窗、关键假设、最小验证实验、90 天计划。

**假设版**必须保留：假设版标识、九窗假设、缺失信息、验证问题；不含评分、TOP3、90 天计划。

## 三、文件与保存

- **单文件 HTML**：CSS 内联，不引用 CDN、外部字体、外部图片或 JS 依赖。
- **默认保存位置**：当前工作区根目录；用户指定目录时以用户为准。
- **命名**：`九窗分析-<产品/服务名>-<YYYYMMDD>-<版本>.html`
  - 版本：`快速版` / `标准版` / `深度版` / `聚焦版` / `假设版`
- **回复**：生成后在对话末尾给出完整路径，并用一句话说明包含哪些模块。
- **无法写文件时**：在回复末尾附上单文件 HTML 代码块，并说明可保存为 `.html` 打开；不得静默跳过。

---

## 四、生成顺序

1. 先在内部完成 Markdown 分析内容，不要先发出半成品。
2. 按档位选择简版/完整版/聚焦版。
3. 读取 `assets/report-template.html`，理解结构与样式。
4. 用真实分析内容替换全部示例数据；删除所有"示例数据"标记。
5. 按版本模块表增删区块：快速版删除评分表与 TOP3，仅保留 0-30 天阶段作为“先做一件事”；聚焦版保留矩阵、假设、验证计划。
6. 在浏览器打开检查：1440px 与 390px 宽度、打印预览。
7. 清理模板注释中不需要的重复块，确保机会卡数量与实际机会一致。
8. 在最终回复末尾附上文件路径与一句话模块说明。

## 五、视觉规范

### 5.1 颜色语义

- **时间维度**：过去用冷灰蓝，现在用主色（深青/墨绿），未来用暖色（琥珀）。
- **优先级**：高=红/深橙，中=琥珀，低=灰。
- **创新类型**：功能=蓝，体验=青，模式=紫灰，跨界=棕。
- **标注**：【事实】中性灰底；【推断】浅黄底；【假设·待验证】浅红底。

颜色只用于区分含义，不做装饰性渐变。

### 5.2 排版

- 字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`。
- 正文 14-15px，行高 1.7；标题层级不超过 3 级。
- 卡片：白底、1px 边框、8-12px 圆角、轻阴影；避免大面积重色块。
- 内容宽度最大 1200px，页面左右留白 ≥24px。

### 5.3 响应式与打印

- 900px 以下：3×3 矩阵改为纵向堆叠，每行带时间标签。
- 600px 以下：机会卡、评分表改为单列；表格允许横向滚动但页面本身不得横向滚动。
- 打印（A4）：隐藏交互元素；`break-inside: avoid` 应用于机会卡与 TOP3 卡；确保打印预览无内容截断。

## 六、标注规则

- 每个窗口的关键事实必须带【事实】【推断】或【假设·待验证】标记。
- 机会卡必须显示来源窗口（如"窗口 4 · 6 · 7"）。
- 置信度必须显示在机会卡与评分表中；快速版可只显示"高/中/低"。
- 矛盾洞察使用独立卡片 + 强调边框，不能用普通段落淹没。
- 页脚注明："本报告由九窗法分析生成；标注为推断/假设的内容需进一步验证。"

## 七、自检清单

### 通用

- [ ] 单文件、离线可打开，无外部请求。
- [ ] 至少 1 条矛盾洞察被视觉强调。
- [ ] 所有推断/假设均有标记，无编造数据。
- [ ] 页脚包含信息完整度、生成时间与免责说明。
- [ ] 已给出完整文件路径。
- [ ] 1440px 与 390px 宽度下无页面级横向滚动。
- [ ] A4 打印预览中卡片不被截断。

### 快速版

- [ ] 9 个窗口全部呈现，每窗 1 条判断。
- [ ] 含 1 条关键矛盾、3 个类型不同的机会、先做一件事（仅保留 0-30 天阶段）。
- [ ] 不含评分表与 TOP3。

### 标准/深度版

- [ ] 9 个窗口全部呈现，每窗 2-3 条要点。
- [ ] 含跨窗洞察（矛盾/时间链/层级链）。
- [ ] 含机会卡（类型、来源窗口、推导链、评分、置信度、最小验证）。
- [ ] 含评分表、TOP3、90 天计划。
- [ ] 深度版含情景分析与 12 个月路线图。

### 聚焦版

- [ ] 含新系统边界、聚焦九窗、关键假设、最小验证、90 天计划。
- [ ] 不套用完整评分与 TOP3。

### 假设版（仅用户明确要求时）

- [ ] 明显标注"假设版｜缺失 X 项"。
- [ ] 不含评分与 TOP3。
- [ ] 含缺失信息与验证问题。

---

## 八、禁止事项

- 不引用外部 CDN、字体、图片或统计脚本。
- 不保留模板中的示例产品、示例数字或示例结论。
- 不得因为用户没有要求就跳过 HTML 生成。
- 不得把快速版 HTML 删到只剩 3 段摘要。
- 不省略跨窗矛盾洞察，不能把 9 窗压成 3 段摘要。
- 不在假设版中加入评分表或 TOP3。
- 不把评分表做成无区分度的装饰性图表。
- 不在 HTML 中写入真实企业敏感数据以外的占位符（生成后必须替换干净）。
