# 产品创新九窗法工具包

## 一、快速启动模板使用说明

当用户尚未提供完整信息时，先判断 4 项必需信息是否齐全；不足则引导用户补齐或填写 `assets/quick-start-template.md`。

**使用场景**：

- 用户只说"帮我分析一下我的产品"，但未提供具体信息。
- 用户描述了部分挑战，但缺少目标用户或核心指标。
- 用户希望获得更系统、更深入的分析。

**引导话术**：

```
九窗分析需要 4 个锚点，缺了只能靠猜。请先确认：

1. 你的产品/服务/内容是什么？主要解决什么问题？
2. 主要用户/客户/受众是谁？
3. 当前最想解决的挑战是什么？主要卡在哪个环节？
4. 目前有哪个核心指标或可观测数据？

4 项齐全后我会直接开始分析；不想逐条写，也可以填写这份模板。
```

**非产品背景用户提示**：

- 子系统 = 你的产品/服务由哪些功能、环节或步骤组成。
- 系统 = 你提供的完整产品/服务/内容。
- 超系统 = 用户使用它的完整场景、上下游与平台规则。
- 不需要产品经理术语；用"你的产品/服务/内容"描述即可。

## 二、不适用场景与替代建议

九窗法适合"产品/服务层面的系统性创新诊断"，不适合所有问题。遇到以下情况，直接说明不适用，并建议替代方法，不强行套 3×3 矩阵：

| 场景 | 为什么不适用 | 建议替代 |
|---|---|---|
| 纯需求排期、项目管理 | 缺少产品系统与创新目标 | 直接用优先级排序方法（RICE/ICE） |
| 纯财务核算、成本测算 | 不涉及产品结构与演进 | 财务建模或单位经济性分析 |
| 纯法律合规判断 | 需要专业合规意见 | 咨询法务/合规专家 |
| 纯技术选型 | 九窗不提供技术比较维度 | 技术评估矩阵 / PoC |
| 纯用户访谈设计 | 属于用户研究执行层 | `discovery-interview-prep` / JTBD |
| 单一功能的具体交互稿 | 问题颗粒度小于九窗分析单元 | 可用 SCAMPER 做局部改进 |

## 三、常见场景快速诊断

每个场景给出重点窗口、追问方向与创新方向。重点窗口用于分配分析精力，但**仍须覆盖全部 9 窗**。

### 场景 1：用户增长放缓

- **重点窗口**：5（产品现状）→ 8（产品创新）→ 6（行业现状）
- **创新方向**：获客路径、留存优化、价值主张升级
- **追问**：
  - 增长放缓主要在哪个环节？（获客/激活/留存/推荐/变现）
  - 核心用户的使用频率和时长有什么变化？
  - 竞品的增长策略是否出现明显变化？
  - 行业是否出现新的流量入口或用户习惯变化？

### 场景 2：功能同质化严重

- **重点窗口**：4（功能现状）→ 7（功能创新）→ 1（功能演进）
- **创新方向**：差异化功能、交互创新、技术升级
- **追问**：
  - 与竞品相比，差异化点在哪里？
  - 用户最常用和最不满意的功能分别是什么？
  - 是否有新技术可以重新定义该功能？
  - 该功能历史上如何演进？下一代形态可能是什么？

### 场景 3：商业化效果不佳

- **重点窗口**：5（产品现状）→ 8（产品创新）→ 9（生态创新）
- **创新方向**：商业模式创新、变现路径优化、生态合作
- **追问**：
  - 当前主要变现方式与收入结构是什么？
  - 用户的付费意愿与付费能力如何？
  - 是否可通过增值服务、订阅、交易佣金拓展收入？
  - 行业内有哪些可借鉴的商业模式？

### 场景 4：新产品方向探索

- **重点窗口**：6（行业现状）→ 9（生态创新）→ 3（行业演进）
- **创新方向**：市场机会识别、需求挖掘、产品定位
- **追问**：
  - 目标行业的规模与增长趋势如何？
  - 行业内有哪些未被满足的痛点？
  - 技术、政策、社会变化是否会催生新需求？
  - 团队能力适合切入哪个细分领域？

### 场景 5：增长瓶颈 / 第二曲线

- **重点窗口**：2（过去成功要素）→ 5（现在瓶颈）→ 8（未来产品形态）→ 9（生态位）
- **创新方向**：价值主张迁移、客群拓展、产品形态重构
- **追问**：
  - 过去三年增长主要靠什么？这个引擎现在还剩多少效力？
  - 现有用户的终身价值是否已被充分挖掘？
  - 是否有相邻客群或相邻场景可以复用核心能力？
  - 如果今天重新做这个产品，会做成什么样？

### 场景 6：跨界创新

- **重点窗口**：3（行业演进）→ 6（行业现状）→ 9（生态创新），并与 4/7 交叉
- **创新方向**：跨行业模式迁移、能力复用、生态合作
- **追问**：
  - 哪个相邻行业已经解决了类似问题？它的解法是什么？
  - 本产品的核心能力还能服务于哪些非典型场景？
  - 跨界的门槛是技术、渠道、合规还是品牌认知？
  - 是否存在平台或生态伙伴可以借用？

## 四、话术模板库

只保留五类必要话术，避免与其他文档重复。

### 4.1 必需信息补全（≤4 问）

```
在开始九窗分析前，我需要确认 4 个关键信息：

1. 产品/服务是什么：具体做什么，帮用户完成什么任务？
2. 目标用户/客户/受众：主要服务哪类人或组织？
3. 当前挑战：最想解决什么问题？主要卡在哪个环节？
4. 核心指标：目前有哪个关键数据，或你希望验证什么指标？

4 项齐全后我会直接输出分析，不再追问。
```

### 4.2 信息仍缺时的回应

```
目前还缺少：<缺失项>。这些信息决定窗口 X/Y 能否成立；缺了只能靠猜，结论不可用。请补充后我再开始分析。
```

### 4.3 二次聚焦邀约

```
如果您想深入某个机会，我可以把【机会名称】当作一个新的"系统"，再跑一次九窗分析，重点看它的现在/未来与上下游影响，并给出最小验证实验。回复编号即可。
```

### 4.4 对象澄清

```
您提到的"【关键词】"，我需要确认分析对象：您指的是【推测1】，还是【推测2】？

确认后我会按九窗法展开，不会在这个问题上反复追问。
```

### 4.5 场景确认（4 项齐全后）

```
根据您的描述，我理解您当前最关注的是【用户增长放缓/功能同质化/商业化不佳/新产品方向/增长瓶颈/跨界创新】。

我将重点围绕以下窗口展开：
- 【窗口 X】
- 【窗口 Y】
- 【窗口 Z】

如果理解有偏差，请纠正；确认后我按九窗法展开。
```

## 五、常见失败模式与修正

| 失败模式 | 典型表现 | 修正动作 |
|---|---|---|
| 无锚点 | "用户体验不好""行业在增长" | 补事实、数据或具体事件；至少每窗 1 条 |
| PEST 化 | 窗口 3/6/9 全是宏观趋势 | 每条超系统事实必须说明"通过什么路径影响本产品" |
| 9 窗平均用力 | 每窗一句话，没有重点 | 锁定 1-2 个焦点子系统，重点窗可写 4 条，其余 2 条 |
| 机会与窗口脱节 | 机会很像咨询套话 | 写完整推导链，至少 2 个来源窗口 |
| 评分通胀 | 全是 4-5 分 | 强制区分度；无依据不给 5 分；降置信度而非抬分 |
| 未来许愿 | "AI 化、平台化、生态化" | 每个未来判断必须从现在层某条事实推出来，并标确定性 |
| 报告过长 | 万字长文、结论难找 | 按输出档位控制篇幅；矩阵只放一句话结论 |
| 信息不足硬分析 | 9 窗全是"推断"，用户拿不到可执行结论 | 先过 4 项信息门槛，不齐只输出补全请求 |
| 无休止追问 | 一轮接一轮要信息 | 最多 2 轮；第一轮≤4 问、第二轮≤3 问，仍缺则停止分析 |
| 术语劝退非专业用户 | 满口"子系统/超系统/窗口" | 先用通俗语言解释，再用术语；允许产品是实体服务、课程、社群、内容 |

## 六、质量检查清单（详细版）

交付前逐项检查：

- [ ] 4 项必需信息是否齐全？不齐是否只输出了补全请求、没有输出九窗？
- [ ] 是否声明了系统边界（系统/焦点子系统/直接超系统/时间尺度）？
- [ ] 是否覆盖全部 9 个窗口？
- [ ] 每窗是否 2-4 条，且包含事实锚点、变化、含义、机会线索？
- [ ] 每窗是否至少 1 条带数字或具体事件？
- [ ] 未来窗是否标注确定性（高/中/低）与依据？
- [ ] 超系统窗口是否避免了无关宏观趋势？
- [ ] 是否至少产出 1 条矛盾/张力洞察？
- [ ] 是否有 1 条时间链和 1 条层级链？
- [ ] 每个机会是否有推导链和至少 2 个来源窗口（或标"单窗机会"）？
- [ ] 每个机会是否有最小验证动作？
- [ ] 评分是否有区分度、置信度、门槛判定？
- [ ] TOP3 是否覆盖不同风险类型？
- [ ] 每个 TOP3 是否有证伪条件与复盘节点？
- [ ] 是否把"事实/推断/假设"分开标注？
- [ ] 是否避免了编造市场数据？
- [ ] 篇幅是否符合档位？追问是否不超过 2 轮、每轮不超过 4 问？

## 七、后续深化方向

用户希望进一步深化时，提供以下方向（不要一次性全展开）：

1. **详细设计**：功能模块、交互流程、信息架构。
2. **技术方案**：实现路径、关键技术选型、技术风险。
3. **商业模式**：盈利模式、定价策略、运营策略、增长飞轮。
4. **风险评估**：市场、技术、竞争、法规风险及应对。
5. **原型与验证**：快速原型、用户测试计划、迭代策略。
6. **指标体系**：北极星指标、过程指标、A/B 测试方案。

## 八、输出质量自检问题

输出前反问自己：

1. 用户能否从报告中一眼看到九窗全貌与最关键的 3 个结论？
2. 每个机会是否都能追溯到具体窗口事实，而不是"看起来合理"？
3. 是否指出了至少一个"过去的优势正在变成未来的阻力"？
4. 评分能否支撑"先做哪个、后做哪个、不做什么"的决策？
5. 用户是否知道下一步该验证什么、怎么验证？
6. 是否清楚区分了事实、推断和假设？
