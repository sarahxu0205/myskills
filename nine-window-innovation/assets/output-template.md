# 九窗法输出模板

> 模板 0 用于信息拦截；模板 A/B/C 默认同时生成 HTML；模板 D 为版本映射规则。

---

## 模板 0：信息补全请求（≤400 字）

适用：4 项必需信息缺任一。只补全，不输出九窗矩阵、机会、评分或 TOP3。

```markdown
## 先补齐 4 个关键信息，再做九窗分析

九窗分析需要 4 个锚点；缺少它们，窗口 1-9 只能靠猜，结论不可用。

| 必需信息 | 当前情况 | 为什么需要 | 请补充 |
|---|---|---|---|
| 产品/服务是什么 | <已具备/部分具备/缺失> | 决定系统边界与焦点子系统 | <缺失时的问题> |
| 目标用户/客户/受众 | <已具备/缺失> | 决定窗口 2/5/8 的判断 | <缺失时的问题> |
| 当前最想解决的挑战 | <已具备/部分具备/缺失> | 决定重点窗口 | <缺失时的问题> |
| 核心指标或可观测现状 | <已具备/缺失> | 判断问题严重度与机会价值 | <缺失时的问题> |

请一次性回复缺失项；补齐后我会直接输出标准报告，不再追问。
```

不要写"回复继续即分析"，也不要在这条回复里给九窗推断。

适用：4 项必需信息齐全 + 用户明确要"先给个判断"。不展开评分表与资源配置。默认同时生成简版 HTML（矩阵 + 矛盾 + 3 个机会 + 先做一件事）。

## 模板 D：HTML 报告版本映射

默认生成规则：快速版 → 简版；标准/深度 → 完整版；二次聚焦 → 聚焦版；假设版仅用户明确要求时生成。

| 模块 | 快速版 | 标准/深度 | 聚焦版 | 假设版 | HTML 区块 |
|---|---|---|---|---|---|
| 分析边界与假设 | 是 | 是 | 是 | 是 | Header 边界条 |
| 产品/服务概况 | 简要 | 是 | 简要 | 简要 | Header 信息卡 |
| 九窗矩阵 | 是（每窗 1 条） | 是（每窗 2-3 条） | 是（每窗 1-2 条） | 是（假设版标注） | 3×3 矩阵网格 |
| 逐窗分析 | 矩阵格内 | 独立章节 | 矩阵格内 | 矩阵格内 | 矩阵 / 正文 |
| 跨窗洞察与矛盾 | 1 条关键矛盾 | 3-5 条 | 1 条关键矛盾 | 1 条假设矛盾 | 洞察卡片 |
| 机会清单 | 3 个简卡 | 完整机会卡 | — | — | 机会卡列表 |
| 评分表 | — | 是 | — | — | 评分表 + 分数条 |
| TOP3 | — | 是 | — | — | 三张详情卡 |
| 90 天计划 | 仅第一步 | 是 | 验证计划 | — | 三阶段路线图 |
| 假设与缺口 | 简要 | 是 | 是 | 是 | 底部信息区 |
| 页脚 | 是 | 是 | 是 | 是 | 信息完整度/时间/免责 |
